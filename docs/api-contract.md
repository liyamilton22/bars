# API-контракт

Базовый адрес: `http://localhost:5000`. Все тела запросов и ответов в формате JSON.
Допустимые статусы заявки: `New`, `InProgress`, `Closed`, `Cancelled`.

## Таблица API

| Метод и путь | Тело запроса | Успех | Возможные ошибки |
|---|---|---|---|
| GET /api/tickets | — | 200, массив заявок или `[]` | 401 |
| GET /api/tickets/{id} | — | 200, объект заявки | 401, 404 |
| POST /api/tickets | title, siteId, description | 201, id, number, status: New | 400, 401, 403 |
| PATCH /api/tickets/{id}/assignee | assigneeUserId | 200, обновлённая заявка | 400, 401, 403, 404 |
| PATCH /api/tickets/{id}/status | status | 200, обновлённая заявка | 400, 401, 403, 404, 409 |

Правила:
- При создании клиент не присылает `id`, `number`, `status` и исполнителя: их определяет сервер.
- Пустой список возвращает 200 и `[]`, а не 404.
- Назначение исполнителя и смена статуса это два разных запроса. Назначение не меняет статус.
- Метода DELETE нет: отмена заявки это смена статуса на `Cancelled`.
- Права проверяет сервер: диспетчер создаёт заявки, назначает исполнителя и отменяет заявку; исполнитель меняет статус только своих заявок (New → InProgress, InProgress → Closed).
- Исполнитель в GET /api/tickets видит только назначенные ему заявки, диспетчер видит все.

## Примеры

### GET /api/tickets

Ответ 200:

```json
[
  {
    "id": 1,
    "number": "REC-0001",
    "title": "Замена кабельной линии, этап 1",
    "siteId": 3,
    "siteName": "ПС Северная",
    "assigneeUserId": null,
    "status": "New",
    "createdAt": "2026-09-20T09:30:00Z"
  }
]
```

### GET /api/tickets/{id}

Ответ 200:

```json
{
  "id": 1,
  "number": "REC-0001",
  "title": "Замена кабельной линии, этап 1",
  "description": "Контроль сроков замены кабеля на участке 1",
  "siteId": 3,
  "siteName": "ПС Северная",
  "createdByUserId": 1,
  "assigneeUserId": null,
  "status": "New",
  "createdAt": "2026-09-20T09:30:00Z",
  "plannedDate": null,
  "completedAt": null
}
```

Ответ 404, если заявки нет:

```json
{ "error": "Заявка не найдена" }
```

### POST /api/tickets

Запрос:

```json
{
  "title": "Замена кабельной линии, этап 1",
  "siteId": 3,
  "description": "Контроль сроков замены кабеля на участке 1"
}
```

Ответ 201:

```json
{
  "id": 1,
  "number": "REC-0001",
  "status": "New"
}
```

Ответ 400, если не заполнен заголовок или такого siteId нет:

```json
{ "error": "Поле title обязательно" }
```

### PATCH /api/tickets/{id}/assignee

Запрос:

```json
{ "assigneeUserId": 2 }
```

Ответ 200 (статус остаётся прежним):

```json
{
  "id": 1,
  "assigneeUserId": 2,
  "status": "New"
}
```

Ответ 404, если заявки нет. Ответ 400, если пользователя с таким id нет.

### PATCH /api/tickets/{id}/status

Запрос:

```json
{ "status": "InProgress" }
```

Ответ 200:

```json
{
  "id": 1,
  "status": "InProgress"
}
```

Ответ 409, если переход недопустим (например, из Closed в InProgress):

```json
{ "error": "Недопустимый переход статуса: Closed → InProgress" }
```

Ответ 404, если заявки нет. Ответ 403, если исполнитель меняет статус чужой заявки.

## Коды ошибок

| Код | Когда |
|---|---|
| 400 | неверные или пустые поля в теле запроса |
| 401 | пользователь не вошёл в систему |
| 403 | роль или принадлежность заявки не позволяют действие |
| 404 | заявка не найдена |
| 409 | недопустимый переход статуса |
