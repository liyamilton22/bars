# Матрица требований

Связь критериев приёмки из ЛР1 (`lab-01-requirements.md`, раздел 11) с моделью данных (`data-model.md`) и API (`api-contract.md`).

| Требование ЛР1 | Критерий | Поле или сущность | Запрос | Кто выполняет |
|---|---|---|---|---|
| Создать заявку | AC-01 | Ticket: title, siteId, description; при создании сервер задаёт id, number, status = New | POST /api/tickets | Диспетчер |
| Назначить исполнителя | AC-02 | Ticket: assigneeUserId (FK → User.id); status остаётся New | PATCH /api/tickets/{id}/assignee | Диспетчер |
| Перевести в работу | AC-03 | Ticket: status (New → InProgress) | PATCH /api/tickets/{id}/status | Назначенный исполнитель |

## Пояснения

- **AC-01.** Клиент присылает только `title`, `siteId` и `description`. Поля `id`, `number` и `status` определяет сервер, в ответе приходит 201. Сетевой объект выбирается из справочника Site, в заявке хранится только `siteId`.
- **AC-02.** Назначение исполнителя это отдельный запрос и отдельное поле. Статус при этом не меняется: после назначения заявка остаётся в состоянии New.
- **AC-03.** Смену статуса выполняет только исполнитель, которому назначена заявка. Если заявку пытается изменить другой исполнитель, сервер отвечает 403. Недопустимый переход статуса даёт 409.
